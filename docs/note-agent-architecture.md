# 笔记 Agent：运行与验收

## 技术选择

沿用 TypeScript/Node HTTP、原生 fetch SSE、React 宿主和 opaque-origin iframe。没有新增 Python 服务或 LangChain/LangGraph；当前目标是让已有状态、文件版本和原生画布命令形成一条可诊断链路，而不是增加第二套状态系统。

Qwen 的工具调用不是执行凭据：只有真实 `tool_calls` 的执行结果、持久化版本和浏览器反馈可信。参考 [Qwen 工具调用文档](https://qwen.readthedocs.io/en/latest/framework/function_call.html)。底层模型的协议偏差必须由应用处理，不能通过正文 XML 直接执行代码。

## 职责

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 任务与完成条件 | `server/agentPolicy.ts` | 区分聊天、创建、修改，否定要求不触发创建；有界纠正缺失产物和虚报成功 |
| 工作记忆 | `server/agentContext.ts` | 将完整结束的旧调用／结果对归档为文字回执，保留最近调用原始参数及源码页；不向模型提供伪参数、不改写保存历史 |
| 文件读取 | `server/fileIO.ts` | 对挂载目录的 ENOENT/ENODATA/EIO/EBUSY 有界重读同一文件；不创建替代文件或身份，持续失败仍明确报错 |
| 模型传输 | `server/agentTransport.ts` | 仅在流尚未接受前重试短暂连接/429/网关错误，不重放已接收流和已执行工具 |
| 无进展检测 | `server/agentProgress.ts` | 连续三次读取同一版本和同一页后提示推进，并在已有编辑权限时暂收起重复读取入口；不同区域、搜索和真实编辑仍可用，不降低正常100轮额度 |
| 调度与版本 | `server/chat.ts` | 单轮生命周期、停止、工具幂等、工作区、源文件、SSE 与保存边界 |
| 预览验证 | `server/agentPreview.ts`、`data/appPreview.ts` | 只接受当前轮次预期作品的受限报告，检查运行错误、显式节点数量和 ID |
| 源码／DOM 对照 | `server/agentDom.ts` | 对照完整运行时 ID 列表，检查同一代码块内查询缺失容器后无条件测量的空引用风险；不执行生成代码，不把它称为完整交互证明 |
| 源码 | `server/appSource.ts`、`server/chatHtmlStore.ts` | 哈希、精确原子替换、JS/HTML 校验、不可覆盖版本与独立试用状态 |
| 依赖与流式投影 | `data/appLibraries.ts`、`data/htmlLibraryStream.ts` | 固定依赖目录，使用真正的 HTML 解析器识别 CDN 标签；相同版本 D3/Mermaid 按顺序使用本地镜像，原始源码不变 |
| 交互宿主 | `components/HtmlAppView.tsx`、`data/htmlRuntime.ts` | 单实例增量解析、依赖安装、状态、隔离、静态快照及实际运行反馈 |
| 知识图点击检查 | `components/AppPreviewCheck.tsx` | 复用共享运行时建立短暂、不持久化的预览副本，探测节点解释；不在用户实例上自动点击，不提供状态／历史写入回调 |
| 画布命令 | 现有 HTML 宿主与原生 embeddable | 手动拖框导入、独立实例、确认应用、历史和导出，不由模型直接写画布 |

创建完成条件是有效源码已经保存，而不是模型说“创建成功”。有浏览器反馈时，明确的运行错误或显式要求未满足会进入同轮局部修正；仍失败则保留源码并明确报告，不当作验收成功。没有浏览器报告时标记未自动验证，不能称为视觉或交互验收通过。

## 恢复边界

- 正常工具往返 100 轮，失败／恢复单独最多 100 轮；取消和整轮 600 秒时限不重置。
- 缺失作品／未执行修改最多 3 次完成纠偏；正文伪工具调用保留一次协议纠偏。
- 长度截断最多接续 2 次；使用同一应用解析器和卡片，不重复此前源码。
- JavaScript 语法错误最多 6 次局部修复（每次重读失败草稿）；实际预览／明确 CSS 诊断最多 6 次局部修正。都共用绝对时限，不会自动确认画布应用。
- 引用源码工作上下文 120,000 字符，累计源码阅读上限 192,000 字符；普通笔记阅读仍独立限制。压缩只影响模型工作记忆，不删会话与源码。
- 源码上限 256KB、单次工具参数上限 128Ki 字符；状态和原有隔离限制保留。局部编辑支持唯一文本匹配或已完整读取的行范围（单处最多 200 行），都必须基于当前源码哈希。
- React 19、D3 7.9.0、Mermaid 11.12.2 使用本地打包文件，不依赖外网。支持注册表内固定版本的 D3/Mermaid CDN 标签写法，按顺序投影到相同版本本地文件；不开放任意 CDN、其他版本或 JSX。
- 预览检查不证明知识正确、审美优良或所有业务交互正确。必须保留真实模型、多轮交互和视觉回归。
- 预览反馈检查运行错误、重复 ID、无效 SVG 坐标、知识节点明显重叠／视口裁切及缩成不足28px高的SVG节点，以及用户明确指定的节点数量、ID 和 data-node。复杂图保留可读字号与局部滚动，布局修复须统一计算全部节点和关系，不反复只挪一对节点。没有正在运行的客户端报告时标记未验证，不虚报通过。
- 长行分页按版本累计真实读取的字符区间；读完全部片段后才允许完整行替换，不能因跨页而永远拒绝已读行，也不能仅凭最后一个片段授权未读前缀。
- 协议 v8 提供实际主标题及同状态节点快照：明确要求改标题／保留原节点时，检查真正的渲染结果，不以模型声明或最低节点总数代替。预览刷新期间不复用脏快照，状态校验仅用于缓存一致性，不替代源码 SHA-256 或授权。
- 协议 v9 增加隔离副本中的知识节点选择检查。仅对约定了 `[data-node]` 和 `#explanation` 的图，最多探测60个可见节点；这是合成选择探测，不是原生鼠标／触屏或任意业务的完整证明。副本复用正式 iframe 运行时、初始状态副本与本地依赖，不更换应用服务或数据目录；宿主和副本内部都设为 inert，防止脚本中的 focus() 抢走焦点，不接入状态持久化和画布历史，返回报告后即清理。
- 源码搜索、读取可选 `revision: "baseline"`，只读定位本轮修改前的输入版本，以恢复漏掉的原数据；它不会授权写入。编辑前仍须读取 `current` 候选，原版本不可覆盖。未能取得同版本／同状态预览时不猜测节点集合；这些检查仍不是任意业务语义的自动证明。
- 解释“为什么改成…”或“如何添加…”不会被完成恢复机制强迫转换为编辑任务；真实修改及确认仍是独立流程。

## 测试入口

```sh
node_modules/.bin/vitest run excalidraw-app/tests/agentCore.test.ts excalidraw-app/tests/targetedEditingV2.test.ts --maxWorkers=1 --minWorkers=1
node excalidraw-app/tests/app-libraries-runtime.cjs
AGENT_RUNS=2 node excalidraw-app/tests/agent-productivity.cjs
node excalidraw-app/tests/generated-app-replay.cjs
```

本机 WSL 墙上时钟跳变曾导致 Vitest 3 将实际约250ms的用例判为30秒超时。该版本 runner 的结束检查使用 `Date.now`；遇到此环境问题可在仓库根目录用 `NODE_OPTIONS=--require=./scripts/test-monotonic-clock.cjs node_modules/.bin/vitest run ...`，确保 worker 也加载它（仅传给父进程的 `node --require` 会被 Vitest 过滤）。此预加载仅给测试进程提供与初始时间对齐的单调时钟，不改系统时间，不禁用真实超时，也不进入生产服务或浏览器。

真实回归只使用 3009 与 `.local-data/preview/notes/`，新增 UUID 样例；测试结束只移除自己创建的精确目录。真实 Qwen 测试严格串行，一次仅一个请求／Agent 循环，修复回放也必须等上一项结束，不并发占用上游。不要并行启动多套浏览器回归干扰前台焦点，不在构建高负载期间统计交互延迟。报告位于 `.local-data/acceptance/agent-productivity/`，应区分模型、应用和自动化工具失败，不能挑选一次成功冒充整体成功率。3001 不参与测试。

生成结果回放必须在所选完整批次全部成功后单独运行。默认两轮8例；选择 `AGENT_RUNS=1` 时用对应的 `REPLAY_CYCLES=1` 回放完整四例，不得把不同批次的成功结果拼成全通过。重新加载真实 Qwen 保存的最终源码，遍历全部知识节点并核对解释变化、检查运行错误，再验证窄屏触控。回放使用相同正式界面及本地依赖，不调用模型，仅新增并清理自己唯一命名的回放样例，不修改用户笔记，不以预制业务模块替代生成结果。

## 回归中实际发现的问题

以下是改进依据，不将失败批次改写为成功：

- 初期冒烟虽有 8/8，通过全节点回放仍发现重叠和裁切；随后加入实际几何、命中与可读尺寸检查。
- 一轮严格回归为 7/8，失败是复杂 K8s 图反复只移动局部节点；改为要求数据驱动的统一分组布局，并保留有界局部修复。
- `readable` 批次为 6/8：网络图修改未真正更新主标题，K8s 修改漏掉原节点。协议 v8 改为核对真实标题和同版本／状态下的节点身份，提供只读 `baseline` 以恢复漏掉的原数据。
- `release-large` 45 节点压力样例生成了 48 个节点，但点击时引用了不存在的 `diagram-container`，解释没有联动。此例不算成功；新增保守的源码／实际 DOM 对照和固定回归。该检查不取代真实点击，不承诺发现任意 JavaScript 的所有潜在错误。
- 挂载目录短暂读取错误曾导致已存在的源文件／会话读取失败，现仅对明确瞬态错误重读同一路径，不新建替代身份。
- 上下文归档曾将真实工具名与伪参数保留成错误示例，现完整归档旧调用／结果组，保留最近和进行中的原始调用。
- `release-v8` 完整批次实际为5/8：K8s新增节点有外观却缺少解释数据，网络图修正反复读取同一页直至耗尽100次恢复，另一次K8s修改以传输失败结束，期间用户确认上游异常。前两项属于真实失败，不能归咎于上游；新增无进展检测及隔离点击检查。原失败K8s候选的生产界面回放已证实可以在应用前发现错误，且不会改写试用状态。
- v9初次真实回归的TCP图暴露检查器误判：首节点已默认选中，再点同一节点不会改变解释。该批次已主动停止，不算模型或完整批次通过。检查器改为操作其他节点后再回查首节点，并增加“正常默认选中不误报、首节点真正失效仍报错”的固定回归；这不修改用户应用源码。

历史报告、源码和截图保留在上述项目内验收目录；正式完成率只按对应批次全部真实任务统计，不以单个修复成功抵消其他失败。当前有限样本不能推出生产场景的百分之九十九成功率，也不证明专业知识完整正确。
