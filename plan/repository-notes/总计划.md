# Excalidraw 仓库笔记

## 需求确认摘要

- 在 Excalidraw 画布内编辑，并保存为仓库 `notes/` 下的 `.excalidraw` 文件。
- 本机单用户使用，GitHub 仅通过用户手动 Git 操作同步。
- 使用 `yarn start` 的 Vite 开发服务器。
- 已从干净的 `master` 创建并切换到本地 `aldebaran` 分支。
- 保留现有浏览器文件保存/加载功能；新增仓库保存/打开入口。
- 首次保存输入文件名，后续保存复用并覆盖当前文件；打开使用菜单内文件列表。
- 不建设独立测试实验室，以自动化测试和手工验收替代。

## 可行性结论与官方证据

- Excalidraw 仓库已有 `.excalidraw` 序列化、保存和恢复逻辑，可复用现有 `serializeAsJSON`、`loadFromBlob` 和菜单动作。
- Vite 开发服务器支持通过 `configureServer` 注册自定义 middleware，且该 hook 不会在生产构建中执行，适合本地仓库读写 API：
  [Vite Plugin API](https://vite.dev/guide/api-plugin.html)
- 不涉及数据库、Shopify、飞书或其他第三方 API。

## 数据库影响清单

无数据库、ORM、迁移、外键或索引变更。笔记直接存储为仓库文件。

## 测试验证方案

- API：列表、创建/覆盖/读取、非法扩展名、路径穿越、绝对路径、不存在文件和损坏 JSON。
- 应用：首次保存记录文件名，后续保存复用文件名，文件列表加载并恢复画布，API 失败显示错误且不破坏画布。
- 命令：`yarn test:app --run`、`yarn test:typecheck`、`yarn test:code`，并启动 `yarn --cwd excalidraw-app start` 手工验证。

## 实施轮次

### 第 1 轮：仓库笔记功能

- 目标：实现 Vite notes middleware、客户端服务、菜单入口和打开文件对话框。
- 影响目录：`excalidraw-app/`、`excalidraw-app/vite.config.mts`、`notes/`、`plan/repository-notes/`。
- 数据库操作：无。
- 依赖：现有 Excalidraw JSON 数据 API和菜单组件。

## 范围外与限制

- 仅支持 `notes/` 根目录下的单层 `.excalidraw` 文件。
- 仅开发服务器提供仓库写入；生产静态预览不提供该能力。
- 不实现独立笔记列表页面、登录、协作、云端 API 或自动 Git 提交。
